## Шаг 1 — телефоны

### Чем обоснован формат

Канон — **E.164 без разделителей: `+13238704790`.** Основание не рассуждение, а два прямых
замера через Local Falcon:

1. **Наша собственная карточка GBP** (`gbp_linked: true`, `gbp_location_id:
   locations/1629564570869286863`, place_id `ChIJ9ysncSy_woARe44arhSyTOY`) отдаёт
   `phone: "+13238704790"` — без скобок, дефисов и пробелов.
2. **Так же выглядит поле у Google вообще.** Поисковая выдача Local Falcon по
   «Same Day Appliance Repair Pasadena» вернула 20 карточек конкурентов — **20 из 20** с
   телефоном в форме `+1XXXXXXXXXX`. Это не наша особенность, это формат самого источника.

Плюс schema.org и документация Google по `telephone` рекомендуют международную форму.
Отображаемые строки (`MAIN_PHONE`, `branch.phone`, `tel:`-ссылки, футер, hero) **не тронуты** —
менялась только разметка.

### Что нашёл и что сделал

Было четыре формы записи:

| Форма | Сущностей | Страниц |
|---|---|---|
| `+NNNNNNNNNNN` (верная) | 8443 | 884 |
| `(NNN) NNN-NNNN` | 784 | 702 |
| `+N-NNN-NNN-NNNN` | 35 | 35 |
| `N-NNN-NNN-NNNN` | 1 | 1 |

Правил в два приёма, чтобы не разносить одно и то же по сотням файлов:

1. **Одно место — `mergeCredentials()`** (`src/data/credentials-schema.ts`). Добавил
   канонизацию `telephone` у самой сущности **и у каждой записи вложенного массива
   `location`** — последнее важно, иначе county-хабы продолжали бы отдавать отображаемый
   формат. Одной правкой закрылось 702 → 431 страницы.
2. **Остаток — сырые inline-схемы**, которые через `mergeCredentials` не проходят
   (`Service.provider`-заглушки на brand-страницах, шаблонные литералы в `credentials/*`,
   `price-list/*`). Здесь значение переписано на месте: 43 литерала приведены к E.164
   напрямую, 450 выражений обёрнуты в `toE164(...)` в 448 файлах.

Хелпер **один на проект** — `toE164()` в `src/data/branches.ts:630` (рядом с `MAIN_PHONE`),
`credentials-schema.ts` его импортирует, дубля нет. Импорт добавлен в 448 файлов: в 437 просто
расширена уже существующая строка `import { … } from '…/data/branches'`, в 11 добавлена новая.

**Итог: одна форма на весь сайт — `+NNNNNNNNNNN`, 9263 сущности, 1097 страниц.**

### /contact/ — противоречие разобрано

Корневая сущность `#business` несла телефон Лос-Анджелеса `(424) 325-0520` и при этом адрес
пина West Hollywood `8746 Rangely Ave`. Одна запись описывала два филиала: для Google это
заявка «по адресу 8746 Rangely отвечает номер 424-325-0520», тогда как карточка GBP по этому
самому адресу указывает `+13238704790`. Прямое NAP-расхождение с собственной карточкой.

**Решение:** адрес пина остаётся, телефон приведён к нему — сущность теперь берёт номер
филиала West Hollywood из SSOT (`BRANCHES.find(b => b.slug === 'west-hollywood').phone`).

```
name    : Same Day Appliance Repair
tel     : +13238704790
address : 8746 Rangely Ave, West Hollywood
```

Общий номер `(424) 325-0520` остался везде, где он и есть общий номер: в видимом тексте, в
`tel:`-ссылках, в записи филиала Los Angeles внутри массива `location`. Убран он ровно с одной
сущности — той, что claim'ит адрес пина.

**Осталось несоответствие, которое я не трогал:** у этой же сущности `geo` =
`34.0619, -118.3692`. Это координата Wilshire (старый PMB), а карточка GBP для 8746 Rangely
даёт `34.0800742, -118.384211`. Долг зафиксирован в `docs/current-status.md` как P2 ещё
раньше; в задание этого захода он не входил.

## Шаг 3 — крошки без `item`: правило уже соблюдено, менять нечего

21 случай, все — промежуточная крошка, у которой нет своей страницы. Проверил **каждый
адрес-кандидат живым запросом** по трём пунктам:

| Адрес крошки | Код | Конечный адрес | meta-refresh |
|---|---|---|---|
| `/outdoor/brands/` (13 страниц `/outdoor/brands/*`) | **404** | совпадает | нет |
| `/brands/beko/`, `/brands/big-chill/`, `/brands/bull/`, `/brands/capital/`, `/brands/coyote/`, `/brands/napoleon/`, `/brands/perlick/`, `/brands/weber/` (8 brand-страниц) | **404** ×8 | совпадает | нет |

Все девять — честные 404 (144 КБ, и это не подмена главной: md5 отличается от главной
страницы). По правилу «адрес не существует → `position` и `name` остаются, `item` нет» текущее
состояние **уже верное**. Ничего не менял: 21 до, 21 после.

Замечу для полноты: пока эти девять хабов не существуют, претензию Google «`item` обязателен
у всех, кроме последнего» полностью снять нельзя — единственный способ это сделать, не соврав
ссылкой на 404, был бы вовсе не выпускать уровень крошки. Это изменение вёрстки, и в правило
захода оно не входило.

## Расхождения и находки по ходу

1. **Мёртвый CSS оказался ровно тем, чем казался.** 59 правил, ноль использований класса,
   и в baseline их было столько же — не побочный эффект захода 2.
2. **Одиннадцать файлов имели LF-концы строк**, остальные — CRLF. Мой первый прогон
   перевёл их в CRLF, и git показал полную перезапись 11 файлов (~3400 строк шума при
   двух реально изменённых). Вернул им LF, **пересобрал и перепрогнал все сверки заново** —
   результат побайтово тот же, то есть на вывод концы строк не влияют, но теперь diff
   честный: 649 файлов, +1143 / −1137, по паре строк на файл (единственное исключение —
   `docs/seo-policies.md`, +24 / −4, это и есть переписанный раздел).
3. **`Brand.telephone` на `/outdoor/brands/kalamazoo/`** (`1-800-868-1699`) тоже приведён к
   E.164. Это телефон производителя, не наш, и само поле `telephone` у типа `Brand`
   невалидно по schema.org — оно уйдёт целиком в заходе 4. Формат поправлен, чтобы проверка
   «одна форма на весь сайт» была честной, а не с оговоркой.
4. **`geo` на `/contact/`** остаётся координатой Wilshire вместо WeHo — расходится с
   карточкой GBP. В задание не входило, выношу отдельно.
