## 21:33 — Fix: JPG fallback in HeroSection v2 picture chain

**Что сделано:**
Add `<source type="image/jpeg">` fallback to v2 `HeroSection.astro`
`<picture>` block. Resolves intermittent hero photo invisibility across
all 87 city pillars caused by Cloudflare edge nodes occasionally returning
`text/html` (cached 404) instead of `image/webp`.

**Diagnosis chain (audit before fix):**
- `<picture>` had WebP-only `<source>` + `onerror="this.style.display='none'"`
- When WebP fetch returned text/html (intermittent CDN) → browser decode
  failed → `error` event fired → `<img>` hidden via display:none
- No JPG fallback in source chain → photo invisible until reload
- Hero photos became intermittently invisible across 73 cities (W1-W4)

**Fix — new `<picture>` chain:**
1. WebP `<source>` — fastest, preferred
2. JPG `<source>` — automatic fallback if WebP decode fails
3. `<img src=jpg>` — fallback for ancient browsers without `<picture>` support
4. `onerror` handler removed — JPG always works (file deployed in W1-W4)

**Commits:**
- `7138cec`: fix(hero): add JPG fallback to v2 HeroSection picture block

**Затронуто:**
- `src/components/cities/v2/HeroSection.astro` (8 insertions, 3 deletions)

  now present + img src points to JPG)
