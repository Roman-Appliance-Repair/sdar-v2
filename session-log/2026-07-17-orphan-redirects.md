# 2026-07-17 — Orphan old-site URLs + полная нормализация редиректов

Merge `c3b2cf4c` на main (ветка `fix/orphan-redirects`, worktree wt2). Один файл: `public/_redirects`.
Аудит: `wiki/audits/orphan-urls-2026-07-17.md` (вики `13b0914`).

## Что было сломано

**96 URL из GSC (12 мес) не имели ни страницы, ни правила.** И они **не отдавали 404** — Cloudflare
возвращал **HTTP 200 с главной страницей** (md5 совпадал с `/`). То есть Google видел не ошибки, а
**96 дублей главной**, и в отчёте GSC «404» их не было и не могло быть. Нашлись только диффом
GSC ↔ `dist`.

Из 96: **71 реальная страница** (20 341 показ, 19 кликов) и **25 картинок** (`.webp`, 28 показов,
0 кликов). Картинкам правил не давали — редирект картинки на HTML не помогает никому.

Плюс **459 существующих правил всё ещё были soft** (36 legacy починили 2026-07-16, остальные нет).

## Механика (доказана на проде до правок)

Источник в `_redirects` обязан нести **тот слеш, который несёт запрос**. Иначе Cloudflare правило
не матчит, и статическая заглушка Astro отвечает 200 первой:

```
/outdoor/grill-repair-beverly-hills/   правило СО слешем   -> 301 + Location  (заглушка тоже есть)
/brands/magic-chef/                    правило БЕЗ слеша   -> 200, без Location
```

## Сделано

- **459 источников** нормализованы под слеш. Wildcard/splat не тронуты. Осталось без слеша: **0**.
- **71 orphan-правило** добавлено. Итого 616 правил (615×301 + 1×302).
- **HVAC (5 URL, 8 646 показов) → кросс-доменный 301 на ventahvac.com.** Внутренней цели не
  существует: HVAC-страниц на сайте нет вообще. Цели брались из `ventahvac.com/sitemap-index.xml`
  и каждая проверена на «живость» по md5 — на том сайте та же ловушка, `/ac-repair/` отдаёт 200,
  но это главная. Все 5 целей — реальные топикальные страницы, отвечают 200.
- **`/hollywood-hills/` → `/hollywood/` через 302, не 301** — 2 992 показа, пиллар планируется,
  вес не уступаем.
- **`/price-list/commercial-wine-cooler-repair-cost/`** (6 228 показов, 14 кликов, позиция 12.6 —
  крупнейшая единичная потеря) → `/price-list/wine-cooler-repair-cost/`.
- 48 legacy WordPress брендовых URL → существующая брендовая страница либо профильный
  `/commercial/` хаб.

## Проверка

- Build **1179 страниц, 0 ошибок** (правила не меняют число страниц).
- Прод, **все 71**: 301/302 + верный Location. Ещё отдают 200-главную: **0**.
- Прод, **30 случайных правил** из city/outdoor/commercial/brand семейств (регрессия STEP 1):
  **30/30** верно, 0 soft.
- `hollywood-hills` — **302** подтверждён.
- 5 целей на ventahvac.com — **200**.
- Все внутренние цели проверены на существование в `dist` **до** записи правил.

## Решение, которое НЕ выполнено (намеренно)

Задание просило добавить `hollywood-hills` в `cities.ts`. **Не добавлено.** `CITIES` кормит
areas-панель мега-меню, где стоит явный комментарий «canonical city pillars only — guarantees no
404 links». Слуг без страницы = 404-ссылка в глобальной навигации на всех 1179 страницах. Слуг
добавлять одновременно с пилларом. Задача в бэклоге: `wiki/tasks/2026-08-15-brand-query-ownership.md`.

## Уроки

- **200 ≠ страница есть.** Cloudflare отдаёт главную вместо 404 — потерянные URL невидимы и в
  HTTP-коде, и в GSC-отчёте «404». Проверять md5 против главной.
- **Чужой сайт — та же ловушка.** `ventahvac.com/sitemap.xml` отдаёт HTML; реальная карта в
  `robots.txt` → `/sitemap-index.xml`. Цели редиректа проверять по md5, а не по коду.
- **Картинки — не страницы.** 25 из 96 «orphan URL» оказались `.webp` из image search.
  Их в отчёт по страницам включать нельзя — искажает и цифру, и вывод.
